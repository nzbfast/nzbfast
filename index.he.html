nzbfast הוא מוריד Usenet הבנוי סביב צינור עיבוד במעבר יחיד: כל בייט מפוענח, מאומת ומחולץ תוך כדי ההורדה. בלי מעבר הרכבה, בלי מעבר אימות, בלי מעבר פריקה. כשפס ההתקדמות מתמלא, הקובץ מוכן ותקינותו מוכחת.

למה זה מהיר

כ-97% מהורדות ה-Usenet במעבר יחיד

מדדנו מה באמת מתפרסם ב-Usenet לפני שהחלטנו מה לייעל, ורעיון אחד עושה את רוב העבודה. הכול נמדד ביומן בדיקות הביצועים עם פקודות הניתנות לשחזור.

🚿

מעבר אחד, כמעט לכל צורה

מאמרים מפוענחים ב-SIMD במקום, נכתבים פעם אחת ישירות בהיסטים הסופיים שלהם, ומאומתים ב-PAR2 מתוך אותם חוצצים. הארכיון מחולץ תוך כדי ההורדה, כך שהכרכים שלו לעולם אינם קיימים כקבצים כלל. זה נכון לארכיונים רגילים, מוצפנים ומקוננים, שהם כ-97% מכל מה שמתפרסם, לפי נפח. רק ארכיונים דחוסים באמת ו-7z ברמה העליונה עדיין צריכים מעבר שני, ויחד הם בערך 3%.

🕸️

זמינות איחוד

מאמר "חסר" רק כאשר כל עמוד שדרה מוגדר סירב לו. חשבונאות מדויקת-בלוקים מכריעה שלם / ניתן לתיקון / בלתי אפשרי לפני בזבוז בייטים, מורידה את המינימום המדויק של בלוקי שחזור, ומבטלת הורדות חסרות סיכוי תוך שניות.

🔁

NNTP בצנרת, עשוי היטב

להחזיק כמה בקשות במעוף בכל חיבור זה לא רעיון שלנו, והקליינטים הטובים עושים זאת. שלנו יעיל במיוחד: בארבעה אתרים מדדנו ‎+12% עד ‎+270% מעל סדרתי, וקו מתרווה עם 8 חיבורים במקום 30-50, כך שאתם מקבלים מהירות מלאה בלי להעמיס על הספק שלכם. ב-SABnzbd זה עדיין מגיע כבוי.

צינור העיבוד

נגיעה בכל בייט פעם אחת

המתחרים כותבים את כרכי הארכיון, קוראים אותם בחזרה לאימות, קוראים אותם שוב לחילוץ, ואז כותבים את הפלט, בערך פי 2 כתיבות ופי 2 קריאות. nzbfast עושה זאת במקום:

socket ──TLS──▶ rapidyenc SIMD decode (in place - 4.95 GB/s per core)
                   │
                   ├─▶ pwrite at final offset          (plain posts)
                   │      └─ or: RAR-map translate ─▶ (unlock, if encrypted) ─▶
                   │         pwrite straight into the extracted file
                   │         (the rar volumes never touch disk - plain,
                   │         encrypted and nested archives alike)
                   ├─▶ PAR2 block hasher - every block MD5-verified from the
                   │      decode buffer; verification finishes with the download
                   └─▶ availability ledger - block-exact health, live
פוסט פגום? בלוקים פגומים ידועים ברגע שהמאמרים שלהם נכשלים, המינימום המדויק של כרכי שחזור מורד תוך כדי ההורדה (22 בלוקים הורדו עבור 20 נדרשים, בסבב הבדיקות), והתיקון נוגע רק בטווחים הפגומים. פוסט בלתי אפשרי? הוא מתבטל תוך שניות לאחר שהוריד כמעט כלום, לפני שהמכסה שלך מבחינה.

תכונות מרכזיות

כל מה שהתקנה רצינית צריכה

הרשימה המלאה (כל מתג, כל אינטגרציה) נמצאת בעמוד התכונות.

  • הורדות בקצב הקו: NNTP בצנרת נמדד ב-8.31 Gbps על 10 GbE; הקליינט המהיר ביותר בכל מקטע בדיקה נקי, בכל גודל.
  • צינור עיבוד במעבר יחיד: פענוח, אימות וחילוץ חופפים; כרכי הארכיון לעולם לא נוגעים בדיסק, בין אם הפוסט רגיל, מוצפן או מקונן; צריך פי 1 דיסק היכן שאחרים צריכים ~פי 2. בשחרור מוצפן של 94 GB זה 90 GB שנכתבים במקום 180 GB.
  • זמינות איחוד מרובת ספקים: ניתוב מדויק-בלוקים על פני עמודי שדרה; פסקי דין מקדימים; תיקון בהתאמה מדויקת; ביטול מוקדם של פוסטים בלתי אפשריים.
  • תקציב זיכרון: תקציב RAM גלובלי אחד עם רמות גלישה מדורגות. הוא לעולם לא מבצע swap במכונה שלך: משימת 190 GB מסתיימת בתוך תקציב של 1 GB (~1.1 GB שיא RSS).
  • חידוש בטוח לקריסות: יומן ברמת המאמר פירושו שקריסה או kill −9 באמצע הורדה עולות כמעט כלום: הוא מתחדש, מוריד מחדש רק את מה שלא נשמר.
  • ממשקי API תואמים: API תואם-SABnzbd ו-NZBGet JSON-RPC: Sonarr, Radarr, nzb360 ו-LunaSea עובדים ללא שינוי. ייבוא בלחיצה אחת של תצורת ה-SAB/NZBGet שלך.
  • אינדקסר מובנה: סורק את קבוצות הדיון שלך לאינדקס מקומי הניתן לחיפוש, ומגיש Newznab כדי שגם מחסנית ה-*arr שלך תוכל לחפש בו.
  • קיר פוסטרים עם מטא-נתונים ללא מפתח: אמנות, דירוגים, שחקנים ותקצירים לכל מה שבאינדקס שלך, בלי אף מפתח API להירשם אליו.
  • אוטומציית רשימת מעקב: נקוב בשם סדרה או סרט (ששודר או לא); הם נתפסים ברגע שהם מופיעים, ואז משודרגים באיכות עד שהיעד שלך מושג.
  • קובץ הפעלה יחיד: תיקון (par2) ופריקה (RAR) רוכבים בתוך הבינארי. חלץ, הרץ, סיימת.

מתאים למחסנית שלך

כוון אליו את הכלים הקיימים שלך

Sonarr / Radarr

API מלא תואם-SABnzbd, הוסף את nzbfast כקליינט הורדות "SABnzbd" וזה פשוט עובד: תפיסות, קטגוריות, עדיפויות, ניסיונות חוזרים, סקריפטים לעיבוד לאחר הורדה (חוזה SAB_*), היסטוריה. חזית ה-Newznab גם מאפשרת ל-*arrs לחפש באינדקס המקומי שלך כאילו היה אינדקסר.

nzb360 / LunaSea

הדימון דובר גם את ה-JSON-RPC של NZBGet, שלטי הטלפון הפופולריים מפעילים את nzbfast ללא שינוי. ולוח המחוונים עצמו כולל פריסת טלפון מהמעלה הראשונה למקרים שאתה רחוק מהמסך הגדול.

מגיע מ-SAB או NZBGet?

לחיצה אחת מייבאת את השרתים שלך מהתקנת SABnzbd או NZBGet קיימת (הוא גם קורא את sabnzbd.ini ישירות). תיקיות מעקב, פידי RSS עם מסננים, תיקיות חכמות עם תיוק TV, וכללי ניקוי מגיעים יחד.

נסה אותו בשתי הדקות הקרובות

חלץ, לחץ פעמיים על המשגר, ענה על שלוש שאלות (או תן לו למצוא את תצורת ה-SABnzbd שלך), ולוח המחוונים נפתח. הורדה ראשונה תוך שתי דקות.
